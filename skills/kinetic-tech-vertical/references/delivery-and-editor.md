# 成片与 HTML 视频修改器交付

本文件用于每一版律师口播成片。HTML 修改器是成品的一部分，不能只交 MP4、SRT、静态预览或源代码。用户修改后必须能自己保存并导出带音频的视频。

## 1. 从剪辑开始保留可编辑内容

- `clean-base.mp4`：完成语义剪切、色彩及约定的人物处理，但不含后期标题、人名条、字幕、水印文字、卡片说明或片尾文字的底片。相机本身拍进画面的文字不在此范围。
- 最终音轨：保留本版实际原声与已采用的配乐/音效；建议同时封装进干净底片，以免修改器只导出静音视频。不要拿未经混音的原片音频冒充最终音轨。
- 包装图形、Logo、动画设计与关键帧：保留原文件和时间数据。标题、身份条、卡片、警示条、片尾、水印中的后加文字分别建图层；不能为省事把含文字的整屏动画烘焙成不可改的视频或图片。
- 原版品牌 Logo 保留为图像素材；可改的单位名、片尾律所名、水印文字仍独立保存。修改文字不能重新画造官方 Logo。
- 字幕按最终剪口维护逐条文本、开始和结束时间；所有时间以成片秒数为单位，不混用源片时间。

每个文字对象至少保存：稳定 `id`、用途、`text`、字体、字号、颜色、位置/宽度、开始/结束、显隐区间。需要动画的对象另保存关键帧或动画参数；字幕还保存逐词对齐结果/来源供校准。账号是字符串。

```json
{
  "id": "caption-001",
  "kind": "subtitle",
  "text": "示例字幕",
  "start": 0.2,
  "end": 1.8,
  "fontFamily": "Noto Sans SC",
  "fontSize": 54,
  "color": "#FFFFFF",
  "x": 540,
  "y": 1320,
  "maxWidth": 1000,
  "align": "center"
}
```

这只是数据示例，不是可直接交付的修改器。使用本片实际图层与语义时间，不能把示例字幕或人员占位符带入正式成片。

## 2. 制作修改器

基于本片最终包装工程制作编辑页面，复用同一组图层、字体、时间线和动画，不另做一套视觉上不同的“近似预览”。现有 `assets/example/index.html` 和 `render.mjs` 是渲染示例，**不是已经具备编辑和音视频导出功能的修改器**；执行者必须完成这层实现。

编辑器必须提供：

1. 可播放、暂停、拖动时间的成片预览，并能听到最终音轨。
2. 可选择和修改的文字图层：标题、律师姓名、完整证号、水印文字、卡片说明、警示和片尾文字，以及每条字幕。
3. 文字内容、字体、字号、颜色调整，修改后即时反映到预览。字幕可改起止时间，校验 `0 <= start < end <= duration`，不能静默截断越界数据。
4. 保持标题约 0–5 秒、整屏动画时隐藏人名条、片尾隐藏普通字幕等原有显隐逻辑；文字变长时能检查换行和遮挡。
5. “保存可编辑 HTML”：保存当前设置并可重新打开继续编辑，不能仅存在内存、浏览器缓存或当前会话。
6. “导出视频”：把当前修改与最终音轨合成为真实视频文件，有进度、成功/失败提示和可下载文件。默认 MP4 H.264/AAC；不能把无音轨、空文件、仅 JSON 或改后缀的 WebM 当成 MP4。

优先交付自包含 HTML，把本片媒体、字体和必要代码嵌入，能用指定的桌面浏览器打开。媒体较大时可交付同目录依赖包，但要有相对路径和使用说明；不能引用制作电脑的绝对路径、私有服务、临时 CDN URL 或未打包的 `node_modules`。

浏览器导出可使用经验证的 Canvas/WebCodecs 加封装库，或明确随包提供并验证的本地导出服务。按实现查当前 API 文档，保留依赖版本和许可证。不能把支持格式/音频编码交给猜测：在交付浏览器实测；不支持时在导出前给出具体浏览器/启动方式，不能默默丢弃音轨。

保留现有动画的 DOM/Canvas 渲染逻辑；若需要导出适配层，应让预览与导出共享图层数据、时间计算和关键帧。只有换字或改样式时，不改变动画素材、切口、音频或无关时间。

## 3. 每版真实验收

先验证正式版本，再复制一份作为编辑测试，避免把测试文字留在交付成片里。用实际浏览器完成并记录：

- 播放片头、人物段、整屏动画和片尾；检查本版内容、Logo、字幕位置、人物条和声音。
- 修改标题或水印文字，再修改一条字幕的文字、字号、颜色、字体及起止时间。确保画面上旧字已经替换，无底片旧字残留。
- 测试较长的人名/证号或卡片文案的排版，检查不截断、不越界；正式身份仍使用本次确认值。
- 保存修改后的 HTML，关闭原页面，重新打开保存文件；核对文字、样式、时间、媒体与音轨均被保留。
- 从保存后重开的页面实际导出视频；对照新时间检查字幕出现/消失，验证文字与样式修改已经进入导出文件，动画仍完整。
- 对导出文件运行 ffprobe，确认视频流和音频流、分辨率、帧率、时长；完整解码，并抽帧和试听检查。音轨存在不代表有声音，不能仅检查流数量。
- 正式交付的 HTML 必须回到本版正式文案；从正式 HTML 导出的结果与最终 MP4 在画面、时长和音轨上匹配。不要要求不同编码结果字节一致。

记录浏览器及版本、测试文件路径、改动前后内容、截图/抽帧、导出参数和实际音频检查结果。未执行的步骤保持 pending/blocked，不能根据页面上有按钮就填写通过。

## 4. 交付目录与完成判定

```text
交付/<片名_版本>/
├── final.mp4
├── video-editor.html
├── subtitles.srt
├── cover.png
├── assets/                  # 非内嵌的底片、最终音轨、字体和图形
├── project/                 # 图层/时间数据、包装源码及剪口记录
├── jianying/                # 本次约定的原生草稿与有效素材引用
├── qa/                      # 本版抽帧、编辑/导出测试记录
├── delivery-checklist.json
└── 交付说明.md
```

内嵌在 HTML 的依赖不必再复制一份。目录/文件可以改为清楚的中文名称；必须在说明中标出对应关系、适用浏览器和打开方法。只打包所需文件，保留外部原素材，不擅自删除。

本项目标准含可编辑剪映草稿与指定原生美颜，按 `native-handoff.md` 执行；用户明确变更交付范围时记录原话。缺少原生依赖仍可完成 MP4/HTML 部分，但不能称“全部完成”。正式人员信息和素材只进入私有交付目录，不提交公开技能仓库。

`templates/delivery-checklist.json` 是待填验收表，不是验收证明。状态由实际操作更新，并给出证据路径；没有完成 HTML 编辑、保存重开和带音频视频导出时不得标记交付完成。
